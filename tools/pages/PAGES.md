# The reference pages

Three generated pages that document the game's content. They are not part of
the site — `shinwar.se` serves the game and nothing else — so they live as
Artifacts instead.

| Page | What is on it | Link |
|---|---|---|
| **Manifest** | Every card, relic, implant, mastery, status and keyword | https://claude.ai/code/artifact/e427de99-9f77-47be-b993-ab4f572ca6f1 |
| **Bestiary** | Every enemy and encounter by act, with hull and damage a turn | https://claude.ai/code/artifact/164b0a88-3e7b-4360-a7f7-b1ff7c9bec8e |
| **Anomaly Ledger** | Every event, every option, and the alloy/health economy | https://claude.ai/code/artifact/2aaf1a36-986e-4509-95e4-5b89b84761fb |

**These URLs are the point of this file.** Publishing to the same URL updates
the page in place; publishing without it makes a fourth copy that nobody will
remember to update. If you are Claude and about to publish one of these, pass
the URL from this table as `url`.

## Rebuilding

```bash
npm run pages
```

Writes all three into `tools/out/pages/`, which is gitignored — they are
derived, and a derived file in the diff is a derived file that will be stale.
Then publish each one to its URL above.

## How they are put together

`tools/dump.ts` exports `buildPools()`, which walks the content registries and
returns every pool with its text already generated by `describeCard`,
`describeRider`, `describeImplant` and `describeRunEffects` — the same
functions that print the text on screen in the game. `tools/pages/build.ts`
hands that to three builders, one per page, each of which fills `{{SLOT}}`
markers in a hand-written template under `templates/`.

The split is deliberate: **the design is HTML you edit, the data is generated.**
Changing how a page looks means editing a template. Changing what it says means
changing the game — and the page follows on the next `npm run pages`, with
nobody having to remember that it exists.

Two consequences worth knowing:

- **Nothing on these pages is typed by hand**, so they cannot drift from the
  build the way a maintained list does. If a page is wrong, the game is wrong.
- **`fill()` throws** on a slot the template lacks and on a marker left
  unfilled. A template and a builder that have drifted apart fail the build
  rather than shipping a page with `{{EVENTS}}` printed in the middle of it.

Ordering is fixed by the builders, never inherited from the registries: the
registries sort by id — deliberately, since that is what makes a run
reproducible — but an id-sorted list of display names reads as no order at all.
The Manifest sorts by rarity then name, the Bestiary by act then tier, the
Ledger by event name.
